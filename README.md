# vpn-app

Лёгкий трей-клиент для обхода DPI: под капотом `winws.exe` (zapret), автоподбор
и автопереключение стратегий. Стек: Tauri 1 (Rust-бэкенд + системный WebView2,
без своего Chromium) + чистый HTML/CSS/JS без фреймворков.

## ВАЖНО: приложение требует прав администратора

`winws.exe` ставит драйвер WinDivert, и в его манифесте стоит
`requireAdministrator`. Значит, и само приложение должно быть запущено
с повышенными правами — иначе Windows не даёт породить дочерний процесс
(`CreateProcess` → ошибка 740). Манифест с `requireAdministrator` теперь
вшивается в exe на этапе сборки (`src-tauri/build.rs`), так что достаточно
запустить `vpn-app.exe` и подтвердить UAC.

Для dev-режима: `src-tauri/run.bat` сам перезапускается через UAC, а если
запускать вручную — терминал должен быть **от администратора**.

## Что было сломано и что исправлено

Изначально приложение собиралось и запускалось, но «не работало»: нажатие
«Подключить» показывало «Подключено», хотя обход не включался. Причины были
не в одной строчке, а в цепочке:

1. **Движок не мог запуститься, а UI врал.** Приложение стартовало от
   обычного пользователя → `Command::spawn("winws.exe")` падал с ошибкой 740
   → ошибка нигде не сохранялась, статус оставался `Connecting` → проверка
   «жива ли стратегия» считала `Connecting` успехом → UI показывал
   «Подключено». Теперь манифест требует админа, а любая ошибка запуска
   попадает в статус `Error` и в текст под кнопкой.
2. **Успех определялся как «процесс не упал за 1.5 сек».** Это не имеет
   отношения к работоспособности: winws спокойно живёт и ничего не пробивает.
   Добавлена настоящая проверка (`health.rs`): HTTPS-запрос к `discord.com` и
   `www.youtube.com` — стратегия считается рабочей только если TLS прошёл.
3. **Watchdog штормил переподключениями.** Умерший `Child` оставался в
   состоянии, поэтому каждые 5 секунд запускался новый перебор; параллельные
   переборы убивали процессы друг друга. Теперь мёртвый процесс забирается из
   состояния, а перебор защищён флагом `sweeping` (в один момент времени
   выполняется ровно один).
4. **`std::thread::sleep` внутри async-команды** блокировал воркер рантайма на
   время перебора. Заменён на `tokio::time::sleep`.
5. **Обновление стирало файлы движка и пользовательские списки.** Папка
   заменялась целиком через `remove_dir_all`, и если хоть один файл был занят
   (а `WinDivert64.sys` занят всегда, пока загружен драйвер — см. п. 6),
   удаление успевало снести половину `bin` и падало с «Отказано в доступе».
   Так из `engine/bin` пропали `cygwin1.dll`, `WinDivert.dll` и все `.bin`, а
   winws.exe после этого показывал «система не обнаружила cygwin1.dll».
   Теперь обновление **ничего не удаляет**: только перезаписывает файлы,
   пришедшие в релизе. Любая ошибка оставляет рабочий движок на месте.
   `*-user.txt` и `ipset-all.txt` не перезаписываются вообще. Плюс стратегии
   парсятся **до** замены файлов, чтобы битый релиз не ломал движок.
6. **Драйвер WinDivert не выгружался после убийства движка.** `taskkill /F`
   не даёт winws корректно закрыться, драйвер остаётся в памяти и держит
   `WinDivert64.sys` открытым: файл нельзя перезаписать при обновлении и
   нельзя удалить. Теперь при отключении и на старте выполняется
   `sc stop windivert`, приложение ждёт выгрузки драйвера и только потом
   обновляет файлы. Заодно это чинит ситуацию, когда драйвер «прибит» к
   старой копии движка и новый запуск молча использовал её.
7. **Обновление в dev-режиме писало в `target/debug/engine`**, а не в
   `src-tauri/engine`. Tauri рядом с собранным exe кладёт копию ресурсов, и
   приложение предпочитало её. Теперь exe из `target\<profile>\` работает с
   исходной папкой `engine/`, а установленное — со своей (рядом с exe).
8. **Парсер `.bat`:** искал только `winws.exe"` (вариант без кавычек не
   находился), давал двойные `\\` в путях, и после выкидывания блоков на
   `%GameFilter*%` мог оставить висящий `--new` без фильтра — winws на таком
   падает. Переписан, покрыт тестами.
9. **Кэш стратегий и настройки** писались в `%APPDATA%\strategies.json`
   (у `tauri::Config::default()` пустой identifier). Теперь — в
   `%APPDATA%\com.vpnapp.client\`.
10. **UI:** крестик убивал трей-приложение (теперь сворачивает в трей), текст
    ошибки не показывался вообще, окно 380×320 обрезало открытые настройки,
    кнопка «блокировалась» на время перебора без возможности отменить.
11. **`engine/` не попадал в установщик**, и установленное приложение искало
    движок по dev-пути. Добавлены `bundle.resources`.
12. **Автозапуск** игнорировал код возврата `reg add` — тумблер включался, а
    записи в реестре не было. Теперь результат проверяется, а UI откатывает
    тумблер при ошибке.
13. **Проверка «стратегия жива» засчитывала любой из двух доменов**, поэтому
    стратегия, чинившая только Discord, объявлялась рабочей: YouTube не
    открывался, а статус был «Подключено». Теперь обязателен YouTube
    (`health.rs`, `REQUIRED_HOSTS`), Discord проверяется дополнительно и на
    вердикт не влияет. Плюс читается первый кусок тела ответа: DPI иногда
    пропускает TLS-хендшейк и заголовки, а рвёт соединение уже на данных.
14. **Имя стратегии не отображалось** (`Стратегия: —` при подключении):
    фронтенд искал его внутри объекта статуса, а оно лежит отдельным полем
    события `engine-status`. Теперь во время перебора видно, что проверяется.
15. **Обновление падало по таймауту** («не дочитал архив»): на весь запрос
    стоял общий лимит 60 с, которого не хватало на архив в десятки мегабайт.
    Теперь архив качается по частям, таймаут — на каждый кусок, и есть один
    повтор при обрыве.
16. **Удачная стратегия не запоминалась**: перебор каждый раз начинался с
    первой по алфавиту. Теперь id последней рабочей стратегии хранится в
    настройках и пробуется первой.

Отдельно восстановлен `engine/lists/ipset-all.txt`: он был затёрт заглушкой
(`203.0.113.113/32`), из-за чего правила `--ipset=` не покрывали ничего
(в логе `Loaded 1 ip/subnets`). Данные взяты из `ipset-all.txt.backup`
(32 126 подсетей).

## Структура

```
src-tauri/
├── src/
│   ├── main.rs        # команды для UI, перебор стратегий, трей, сторожа
│   ├── engine.rs      # процесс winws, статусы, watchdog, пути к движку
│   ├── health.rs      # проверка «стратегия реально работает» (HTTPS)
│   ├── strategies.rs  # парсер .bat, кэш стратегий, fallback-набор
│   ├── update.rs      # обновление движка/списков с GitHub
│   ├── settings.rs    # настройки (автоподключение)
│   ├── autostart.rs   # HKCU\...\Run
│   └── paths.rs       # папка конфигурации
├── engine/            # bin/ (winws.exe, .bin, WinDivert) + lists/
├── build.rs           # манифест requireAdministrator + иконка
├── Cargo.toml
└── tauri.conf.json    # окно, allowlist, bundle.resources
src/                   # фронтенд: index.html, style.css, app.js
```

## Как работает подключение

1. `cmd_connect` → перебор стратегий по порядку (если перебор уже идёт —
   второй не запускается). Первой пробуется стратегия, сработавшая в прошлый
   раз.
2. На каждую стратегию: `spawn` → пауза 1.2 с → процесс жив? → проверка
   трафика: HTTPS к `www.youtube.com` и `youtube.com` (обязательные) и
   `discord.com` (дополнительный). Нужно не только получить заголовки, но и
   прочитать первые данные ответа.
3. Прошла — статус `Connected` и имя стратегии в UI. Не прошла — процесс
   гасится, берётся следующая. Все провалились — `Error` с перечислением
   доменов, которые не открылись.
4. Watchdog (раз в 3 с) следит за процессом: умер сам — переподключение,
   начиная со следующей стратегии.
5. Сторож трафика (раз в 90 с) проверяет, что обход всё ещё пробивает DPI;
   после 3 неудач подряд — переключение на другую стратегию.
6. При отключении (кнопка, трей, выход) движок гасится, после чего выполняется
   `sc stop windivert` — иначе драйвер остаётся в памяти, держит
   `WinDivert64.sys` открытым и мешает обновлению файлов.
7. UI не опрашивает бэкенд по таймеру: событие `engine-status` + разовая
   синхронизация при открытии окна.

## Запуск

```
src-tauri\run.bat          # dev, сам запросит UAC
cargo tauri build          # из src-tauri → .msi / .exe
```

Тесты: `cargo test --no-default-features` из папки `src-tauri`. Обычный
`cargo test` не запустится: тестовый бинарник тоже получает манифест
`requireAdministrator` и без UAC падает с ошибкой 740. Флаг
`--no-default-features` отключает фичу `elevate` (только манифест; логика
тестов движок не запускает).

Есть ещё дымовая проверка на живой сети (по умолчанию пропускается):
`cargo test --no-default-features -- --ignored --nocapture` — печатает, какие
домены реально открываются с текущего подключения.

## Известные ограничения

- Проверка стратегии требует интернета: если сети нет вообще, все стратегии
  будут признаны нерабочими (сообщение об этом появится под кнопкой).
- Нет защиты от второго экземпляра приложения: два запущенных клиента будут
  гасить процессы друг друга.
- Игровые профили (`%GameFilterTCP%`/`%GameFilterUDP%`) при парсинге `.bat`
  отбрасываются: их значения задавал `service.bat`, которого в комплекте нет.
- Автозапуск сделан через ключ `HKCU\...\Run`. Так как exe требует прав
  администратора, Windows при входе в систему покажет UAC-запрос. Если это
  мешает — автозапуск стоит перенести на задачу в планировщике с флагом
  «выполнять с наивысшими правами» (`schtasks /RL HIGHEST`), тогда UAC не
  появляется.
- Проверка «стратегия жива» ходит на `www.youtube.com`, `youtube.com`
  (обязательные) и `discord.com` (дополнительный). Если у провайдера
  заблокированы именно они (или сломан DNS), стратегия будет считаться
  нерабочей — список доменов задаётся в `src/health.rs`.
- Полный перебор 20+ стратегий занимает до двух минут: каждый вариант
  проверяется реальным запросом с таймаутом 6 с. Поэтому удачная стратегия
  запоминается и в следующий раз пробуется первой.

## Сторонние компоненты

Код приложения — Rust + HTML/CSS/JS, но в `src-tauri/engine/` лежат файлы из
других проектов, и у них свои лицензии:

| Что | Откуда | Лицензия |
| --- | --- | --- |
| `bin/winws.exe`, `bin/*.bin` | zapret (bol-van/zapret) и сборки на его основе | см. репозиторий zapret |
| `lists/*.txt` | те же сборки | см. репозиторий zapret |
| `bin/WinDivert.dll`, `bin/WinDivert64.sys` | WinDivert | LGPL-3.0 (двойная: GPLv2 / LGPLv3) |
| `bin/cygwin1.dll` | Cygwin | GPL-3.0+ |

Если публикуете репозиторий с папкой `engine/`, приложите тексты этих
лицензий. Альтернатива — не коммитить `engine/`: приложение работает без неё
только после «Обновить стратегии» (оно само скачает движок с GitHub), а до
этого покажет ошибку «не найден движок».
